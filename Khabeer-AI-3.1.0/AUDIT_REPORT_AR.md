# تقرير فحص وإصلاح «الخبير الذكي»

تاريخ الفحص: 17 أغسطس 2026

## النتيجة التنفيذية

أُعيد بناء المسارات الحرجة الخاصة بهوية المتحدث، وحفظ الحوار، وذاكرة الاجتماع، والتوثيق الحي، والأمان، وزمن الاستجابة. لم يعد النموذج مسؤولاً عن تخمين المتحدث من النبرة أو الجنس أو الاسم الوارد في الجملة؛ محرك الخادم وحده يرسل هوية موثقة، بينما تظل الهوية غير المعروفة مجهولة إلى أن يُربط مرشح صوتي باسم صريح.

## الأسباب الجذرية التي وُجدت

- ملفات `SpeakerRegistry` و`SpeakerDiarizer` وأنواعها كانت فارغة، وكذلك مكونات لوحة التحكم والتحليلات.
- ملفات ONNX/WASM وعينات الصوت المرفقة كانت فارغة أو تالفة، لذلك لم يكن هناك نموذج بيومتري صالح للاختبار.
- ملفات المتحدثين كانت تُزامن قبل إنشاء رقم جلسة قاعدة البيانات، ثم يُحلل الصوت تحت رقم آخر.
- كان المتصفح والخادم ينفذان مساري تعرف صوتي متسلسلين، ما يزيد التأخر ويخلق نتيجتين متعارضتين.
- كان التطبيق يحفظ رد الخبير ولا يحفظ النص المنطوق للمستخدم مع اسم قائله.
- بنية الرسائل لم تكن تحتوي حقول هوية المتحدث أو مصدر الرسالة.
- استخلاص نهاية الاجتماع كان ينشئ قراراً ومهمة افتراضيين حتى عند غياب الدليل، ويعيد نجاحاً وهمياً عند فشل قاعدة البيانات.
- بعض مسارات الجلسة والصوت لم تتحقق من الملكية أو المصادقة على نحو كافٍ.
- الدردشة النصية كانت تنتظر طلباً ثانياً للنموذج لإنشاء العنوان، وتقرأ سياق اللوائح أكثر من مرة.

## ما تم إصلاحه

### هوية المتحدث

- سجل متحدثين كامل مع متجه مركزي، عينات متعددة، حد تشابه، هامش فصل عن ثاني أفضل تطابق، ومنع انجراف البصمة.
- رفض النتائج الملتبسة وعدم تحويل الاسم المذكور في الكلام إلى هوية القائل.
- فصل الحالات إلى `VERIFIED` و`CANDIDATE` و`UNKNOWN`؛ لا يرى النموذج الاسم إلا في الحالة الأولى.
- ربط التعريف الذاتي مثل «أنا أحمد» بمرشح المقطع الحالي فقط، مع منع إعادة تسمية ملف موثّق بغير قصد.
- تخزين ملفات المتحدثين في قاعدة البيانات واستعادتها عبر الجلسات، مع ترحيل الملفات القديمة غير المتوافقة إلى حالة تتطلب إعادة التسجيل.
- تحليل تقدمي أثناء الكلام ونتيجة نهائية عند نهاية المقطع، مع نافذة صوت سابقة لبداية الكلام.

### سرعة الرد

- أصبح الخادم المرجع الوحيد لتحليل هوية المتحدث أثناء الاجتماع.
- لا يبدأ إرسال الميكروفون قبل اكتمال اتصال النموذج وإشارة `live_ready`.
- جلب ذاكرة المؤسسة وسياق اللوائح بالتوازي، مع ذاكرة تخزين مؤقت وسقف أقصر للسياق الحي.
- حذف استدعاء النموذج الثاني الخاص بعنوان المحادثة واستبداله بعنوان محلي فوري.
- تخزين النموذج العامل المفضل مؤقتاً، وعدم إعادة المحاولة إلا للأخطاء القابلة لإعادة المحاولة.

### ذاكرة الاجتماع والتوثيق

- حفظ نص المستخدم والنموذج مع `speakerId` و`speakerName` ودرجة الثقة ورقم الدور.
- أداة حية لتسجيل قرار أو توصية أو مهمة أو خطر فور ظهوره، مع منع التكرار.
- تسجيل المسؤول والموعد والأولوية والدليل، مع عدم اختلاق قرار أو مهمة عند غياب الدليل.
- إدراج أسماء المتحدثين الموثقة في السياق التاريخي ومحضر الاجتماع.
- إعادة بناء لوحة المؤشرات لعرض القرارات والمهام والمخاطر الفعلية.

### التدخل المهني

يستمع الخبير ولا يقاطع النقاش الطبيعي. يتدخل عند مخالفة لائحة واضحة، أو خطر مرتفع/حرج، أو تعارض قرارين، أو قرار بلا أساس، أو مهمة بلا مسؤول أو موعد. قبل الاستشهاد بمادة نظامية يستخدم أداة استرجاع اللائحة؛ وإذا لم يجد نصاً صريحاً يقول ذلك بوضوح.

### الأمان

- توقيع جلسات الدخول التطويرية وتعطيلها افتراضياً في الإنتاج.
- إلزام المصادقة لمسارات التضمين الصوتي وصحة النموذج والتسجيل الصوتي.
- التحقق من ملكية الجلسة قبل القراءة أو الكتابة أو الحذف أو إعداد المحضر.
- منع الواجهة من إرسال بصمات وصفية أو أسماء مبنية على طبقة الصوت إلى النموذج كمصدر للهوية.

## اختبارات القبول المنفذة

- نجاح اختبارات سجل المتحدث: تطابق موثّق، إنشاء مجهول، رفض التطابق الملتبس، وثبات المتجه المركزي.
- نجاح اختبار توقيع جلسة التطوير ورفض العبث بها.
- فحص صياغة ملفات TypeScript الخدمية وحل جميع الاستيرادات النسبية.
- التأكد من زوال الملفات المصدرية الفارغة بعد إعادة بنائها.

لم يُنفذ `npm run lint` أو `npm run build` داخل بيئة الفحص لأن الأرشيف لا يتضمن `node_modules` ولم يكن سجل npm متاحاً منها. لذلك يجب تنفيذ فحص TypeScript وبناء Vite بعد `npm ci` في بيئة النشر قبل اعتماد الإصدار.

## القيد المتبقي قبل الإنتاج

النموذج `models/eres2net.onnx` في النسخة الأصلية حجمه صفر، وعينات الصوت المرفقة ليست ملفات صوت قابلة للقراءة. لذلك يعمل النظام حالياً بوضع `ACOUSTIC_FALLBACK` الآمن والمعلن. يلزم تركيب نموذج ONNX حقيقي متوافق، ثم تسجيل ثلاث عينات لكل شخص وإجراء اختبار ميداني بأصوات متعددة وضوضاء وميكروفونات مختلفة قبل اعتماد نسبة الهوية في قرارات حساسة.

## تشغيل الترقية

1. ثبّت الاعتماديات: `npm ci`.
2. اضبط متغيرات البيئة المذكورة في `.env.example`، ولا تفعّل الدخول التطويري في الإنتاج.
3. نفّذ ترحيل قاعدة البيانات: `npm run db:migrate`.
4. ضع نموذج ONNX الصالح في `models/eres2net.onnx` وتحقق من مسار صحة النموذج.
5. شغّل `npm run test:unit` ثم `npm run lint` ثم `npm run build`.
6. سجّل ثلاث عينات صوتية على الأقل لكل متحدث، ثم اختبر اجتماعاً تجريبياً قبل النشر.
